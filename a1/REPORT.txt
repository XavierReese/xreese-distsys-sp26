EXPLANATIONS

- The largest variance comes from Test 6, 4ms variance for a TCP connection

Per-test explanation:
1. Trivial function calls take place on cpu, very lightweight, hence the fast speeds and small variance
2. create/delete does some I/O with the filesystem, but still very fast (and my home directory is small
3. create/delete in tmp - a bit faster and consistent, there is less in my /tmp directory to vary
4. wall clock time - involves communication with the system to get the current time, this seems to be a pricer call given the longer times
5. dict insert - again lightweight, all takes place on CPU
6. TCP connection - longer because of latency over the internet, and varies more depending on example.com's response
7. HTTP - built on top of TCP so takes more time, but is more consistent, likely because its more complex functions can be abstracted and efficiently completed
8. JSON parse - very consistent, probably takes place all on CPU
9. scandir - communicates with filesystem, but low processing so very quick
10. ls -l - longer than scandir because it likely does more unnecessary tasks rather than the purpose built scandir, and scandir is built for python
