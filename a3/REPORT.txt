1. Message Schema

Request:
{
    "method": "insert" | "lookup" | "remove" | "size" | "query",
    "key": string,                                                  // optional
    "value": string,                                                // optional
}


Response: 
{
    "status": "success" | "failure",
    "result": string,                   // for success, optional
    "message": string,                  // for failure, optional
}

EXAMPLES

1.
    {
        "method": "insert"
        "key": "key1"
        "value": "hello world"
    }

    ->

    No Response


2.
    {
        "method": "lookup",
        "key": "key1"
    }

    ->

    {
        "status": "success",
        "result": "hello world"
    }


3.
    {
        "method": "lookup",
        "key": "dne"
    }

    ->

    {
        "status": "success",
        "result": None
    }


4.
    {
        "method": "remove"
        "key": "key1"
    }

    ->

    { "status": success }


5. 
    {
        "method": remove"
        "key": "dne"
    }

    ->

    {
        "status": "failure",
        "message": "key dne not found in table"
    }

6.
    { "method": "size" }

    ->

    { "status": "success", "result": 1 }

7. 
    { "method": "query", "key": "key1"  }

    ->

    { "status": "success", "result": True }

8. 
    { "method": "query", "key": "dne"  }

    ->

    { "status": "success", "result": False }

8. 
    { "method": "dne"  }

    ->

    { "status": "failure", "message": "method dne does not exist"  }

3. Reflections

It makes sense that Insert and Lookup take a lot longer than Query and Remove, as these are the ones that need to send files over the connection rather than just instructions.
We saw similar results in Assignment #1, as the local delete/remove are extremely fast, opening a TCP request is orders of magnitude longer, but then actually reading something back
(an html file) was again even larger. Here, the connection is quicker than through http to the internet, but still it takes a significant delay to transmit the files.

The similarity in timing of query and remove show that their differences are negligible and most of the latency likely comes from the connection between the student machines itself.
