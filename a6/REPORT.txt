3. Explanation / Analysis

The system as a whole is generally a good method of allowing some syncing, and works especially well for new members joining, but it lacks a guaranteed sync.
This is because each peer is only watching the first peer that it found. Therefore, the latest peer to join never has anyone watching it, and some other peers
may also never have been the first to be found by another peer. So some added files won't be propogated throughout the network. The only guarantee
is that the original peer will be linked to all other peers.

In my example, I was 'lucky' that Peer 1 started to watch peer 3, because it meant that no matter which peer I would have added files to, it would have spread
throughout the system. However, this is not guaranteed to happen.

Another issue that I ran into was that with the ND name server, peers which have been closed remain (am I missing a way to remove them?). No matter if there is a way
to remove them manually, you can't always guarantee that this will occur when a peer has crashed or is slowing down significantly and shouldn't be used. However,
in this system the peers latch on to the first one that they find and will not seek new peers to watch, so one peer crashing can separate all of the peers which are linked
to it from the rest of the system.

Overall, this feels like a step toward a functioning peer to peer system, but it isn't complete enough to guarantee survival through crashes or complete syncing.
At scale, these would only be more probable to occur.
